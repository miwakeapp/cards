# Card Field Generation

Provides focused AI operations for resolving card fields that a caller cannot determine reliably from source data and JMDict alone:

- `selectSensesForCard()` determines which already structurally compatible JMDict senses belong on one recognition card.
- `selectAdditionalReadingsForCard()` decides which otherwise valid same-entry pronunciations are useful enough to accept on that card, without ever rejecting the reading established by the encounter.
- `generateSourceGroundedHint()` decides whether a semantic contrast needs a hint and whether the supplied source can support one, then generates the hint and its evidence when possible.
- `minimizeContext()` shortens an already-resolved full context without changing the marked usage or its meaning.

The package owns each operation's canonical prompt, structured-output schema, deterministic output validation, any few-shot examples, supported model registry, and production configuration. Deterministic validation enforces source identity, markup, and other hard invariants. Semantic faithfulness is assessed with the explicitly basis-labeled development corpus in `card_field_generation_evals`; neither the prompt nor character-level checks prove it.

Each operation accepts only the evidence needed for that decision and validates the structured output before returning it.

Context HTML must already be a trusted, sanitized fragment whose intended lexical occurrences were resolved and marked by `card_resolution` or an equivalent acquisition boundary. This package validates the mark structure needed for safe prompting, but it does not repeat target location or deinflection. It preserves supplied structure so target ruby can be restored exactly, but it is not an HTML sanitizer. Sense-selection and hint prompts receive rendered plain text with opaque occurrence sentinels and no source furigana, preventing a reading from leaking through a generated front-side hint. Context minimization instead preserves textual Anki furigana because it is producing a back-side context; exact marked markup is restored after generation.

The focused operations use an agent-selected production baseline: GPT-5.6 Sol at medium reasoning effort for hints, sense selection, and additional-reading selection, and Claude Opus 5 at low effort for context minimization. `PRODUCTION_GENERATION_CONFIGURATIONS` is the single public source of truth for these choices. Callers can override either setting for experiments or operational constraints; they do not need to pass options merely to get the configured baseline. Model-selection evidence and its limitations are documented in `card_field_generation_evals/MODEL_SELECTION.md`.

`selectAdditionalReadingsForCard()` receives one inviolable encounter reading and one or more deterministically compatible alternatives. It returns an ordered include/omit decision and rationale for every alternative. JMDict commonness and expanded reading tags are prompt evidence. Callers can additionally supply BCCWJ LUW2 lemma/reading frequencies, which are analyzer assignments rather than observed ruby counts: magnitude is useful, but a missing pair is never proof that a valid reading is rare.

`generateSourceGroundedHint()` returns an explicit three-way outcome. A generated hint includes two exact rendered-text spans: broad `semanticEvidenceSpan` makes the usage decision auditable, while its nested, sentence-local `hintSourceSpan` bounds the words and relationships the compact hint may reuse. `not-needed` means the selected and contrasting usages are semantically indistinguishable. `source-insufficient` preserves a different fact: a contrast exists, but the encounter cannot fairly support a short cue. Callers create the otherwise-useful card unhinted rather than fabricating a generic hint, and may retain that disposition for later review.

JMDict evidence sent to models uses the checked-in English descriptions for part-of-speech, field, dialect, and miscellaneous tags, rather than opaque abbreviations such as `v5r` or `on-mim`.

Pass a completed-result cache to avoid paying twice for the same validated request. `cacheMode: "use"` reads and writes it, `"refresh"` replaces an existing value after a fresh successful generation, and `"bypass"` does neither. Cache records retain raw structured model output and run the current schema and deterministic validator on every read. A first-attempt response therefore survives a validator-only change when it still passes and automatically regenerates when it does not. Output from a corrective retry is reused only by the same validator version, because the preceding validator error shaped that retry's prompt. The validator version is retained in provenance and also separates concurrent in-flight calls, but it does not invalidate reusable first-attempt output. Identical concurrent calls share one in-flight structured-generation operation even without a persistent cache. A `shared` or result-cache `hit` reports zero incremental `metadata.usage`; `metadata.sourceUsage` and `metadata.sourceGeneration` retain the cost and retry provenance of the generation which produced the value. Prompt-cache controls affect provider routing and billing rather than the semantic completed result, so changing only those controls preserves completed-result cache reuse while producing a distinct current `fingerprints.configuration`; the cached source generation retains its original configuration fingerprint. A cache-write or `onAttempt` observer failure is non-fatal after generation has been paid for: the valid result is returned with `metadata.sideEffectErrors`, avoiding an accidental paid retry.

Every result records content fingerprints for its base prompt, every new corrective round, stable provider-cacheable prompt prefix, structured-output schema, and effective request configuration. GPT-5.6 models and Anthropic receive explicit cache directives, while Gemini uses its implicit prompt cache. Concurrent cold requests sharing a stable prefix wait for one structured-generation round before fanning out, so this optimization applies to production callers as well as the eval runner. One package-level round can itself include the AI SDK's bounded transient HTTP retries. The optional `card_field_generation/file-cache` subpath supplies an append-only JSON Lines result cache for Deno command-line workflows; one instance serializes its writes and recovers from an interrupted final append, but separate processes must not write the same file concurrently.

`selectSensesForCard()` returns a discriminated learner-facing outcome. `selected` contains the complete, explicit, nonempty `senseNumbers` subset: senses used directly plus transparent extensions that would be redundant as separate recognition cards. `no-match` means the source establishes that none of the compatible senses describes the usage. `ambiguous` lists the senses still possible when the source cannot safely distinguish lexical associations that would require separate cards. Both non-selected outcomes are terminal: callers defer rather than inventing a card or treating insufficient evidence as a dictionary mismatch.

Callers remain responsible for adapting generated fields to their workflows and for detecting stale deterministic evidence before passing fully decided input to `card_creator`.
