# Animecards → Miwake card conversion

This workflow converts reviewable Animecards notes in place. A note is eligible only when all of the following are true:

- it has exactly one card;
- its JMDict entry has exactly one sense, unless the explicit multi-sense rollout flag is used;
- its JMDict entry can be identified from a glossary link or an exact headword match, or the explicit entry-selection pass can distinguish several same-spelling entries;
- its recognition-target field does not contain a bracketed usage hint;
- its reading is unique, or the existing Animecards `Reading` field identifies it;
- the exact or inflected target can be located unambiguously in the sentence;
- its full context can be checked and, when necessary, restored against source material, unless the explicit source-less mode accepts the original Animecard context;
- the resulting Miwake Card key does not already exist.

The converter uses JMDict part-of-speech data to locate conjugated forms directly, with the tokenizer as a fallback instead of an authority on unstable token boundaries. It also searches uniquely matched EPUB passages, including excerpts spanning adjacent paragraphs, before rejecting a truncated Animecards excerpt. Recovered paragraph boundaries use plain `<p>` elements rather than ebook classes, IDs, or `<br>` separators. Target location is deterministic; unresolved surfaces are recorded for manual review instead of being guessed by AI. Single-sense cards with short contexts use no AI by default, while longer contexts use a focused operation for minimized-context generation. Pass `--include-multiple-senses` to retain entries with several senses: JMDict spelling and reading restrictions resolve any uniquely compatible sense deterministically, while genuinely ambiguous candidates remain pending for the cached enrichment stage. The flag remains explicit so ordinary single-sense batches keep their established policy during the initial multi-sense rollout. Cases that cannot be validated against JMDict or the EPUB source are recorded instead of being guessed, except when the explicit source-less mode deliberately accepts an Animecard's original context.

Source names are cleaned of known reader-app suffixes. When the source field is empty, the prepare step searches `epub_texts/` and fills the source only if the complete context occurs in exactly one book. URLs from private readers and URLs with authentication or expiry parameters are retained in the manifest for auditing but are not linked on the card. Each candidate's `sourceResolution` records the chosen name, method, URL, and public-URL decision.

Pass `--include-sourceless` to convert notes for which neither the Animecard nor the EPUB corpus supplies a source. This mode accepts the existing Animecard sentence unchanged as the final Full context and leaves the Miwake Card's Source field empty. It still applies the normal entry, target, reading, sense, hint, furigana, minimized-context, duplicate-key, and stale-note validation. It is opt-in because no source exists from which to restore ruby, complete a truncated excerpt, or verify that the original context is faithful.

## Usage

Anki must be running with the Animecards and Miwake note types installed. Both note types must have one card template, because that lets Anki retain the existing card ID and review history during the model change. The installed AnkiConnect must provide `updateNoteModel`; version 25.11.9.0 is known to provide it.

From `anki_updater_prototype/`:

```sh
deno task animecards:prepare
deno task animecards:restore-context generated/animecards-YYYY-MM-DD.json
deno task animecards:enrich generated/animecards-YYYY-MM-DD.context.json
deno task animecards:report generated/animecards-YYYY-MM-DD.context.enriched.json
deno task animecards:apply generated/animecards-YYYY-MM-DD.context.enriched.json
deno task animecards:apply generated/animecards-YYYY-MM-DD.context.enriched.json --write
```

The prepare command reads Anki and writes a reviewable JSON manifest and Markdown audit report; it never modifies the collection. Each candidate contains the complete original note data and a fingerprint. Set a candidate's `approved` property to `false` to hold it back.

Pass `--resolve-entries-with-ai` to handle a Jitendex glossary containing several JMDict links or a selected entry whose recognition-target spelling also belongs to other entries. Explicit source ruby first excludes entries with incompatible readings; an Animecard reading is weaker evidence and does not exclude competing entries before semantic comparison. The pass deterministically marks the intended surface, presents the remaining entries' senses as one numbered list to focused sense selection, and calls focused source-grounded hint generation whenever another semantic usage remains visible from the exact front-side spelling. That contrast includes senses available only through another reading and entries which store the same text in either JMDict form category. If the comparison chooses an unlinked entry whose reading contradicts the Animecard reading, the one linked, reading-compatible alternative may be checked independently and is accepted only when its senses fit the context and produce the required short contrastive hint. A semantically preferred same-reading entry is never overridden this way. Shared-spelling entries may have several senses because this operation selects the entry and senses at the same time; unrelated multi-sense cards remain controlled by `--include-multiple-senses`. No match or a selection spanning entries remains deferred with a distinct skip reason. When the selected usage is secure but the source cannot support a useful hint, the card proceeds unhinted rather than fabricating a cue. A generated hint is omitted from the final card when its `～` boundary notation uniquely distinguishes the selected affix usage; another sense or entry with the same boundary pattern keeps the hint. Independently validated operation results use the package-wide content-addressed `generated/card-field-generation-cache.jsonl`; the orchestration itself is deterministic and is cheaply replayed from those results. The audit report records the allowed IDs, every compared ID, the selected ID, final hint, actual model-and-effort configuration IDs, and context, including sense field and usage tags. Without `--ai-model`, each focused operation uses its independently evaluated production configuration; the flag explicitly overrides the model for both while retaining their respective production efforts.

Preparation searches the matching EPUB passage for every sourced candidate and deterministically derives the minimum source span that the final context must retain. It restores source-authored `<ruby>` and `<rt>`, completes partial sentences, and normally expands an excerpt that cuts into dialogue to the complete outer `「…」` or `『…』` passage. Dialogue spanning at most two EPUB paragraphs is preserved in full. Longer dialogue keeps the target paragraph plus one adjacent paragraph when the target paragraph is shorter than 40 characters, with `……` marking omitted text and balanced outer quotation marks synthesized around the result. Crossed paragraphs are serialized as plain `<p>` blocks. These deterministic elisions are final; other restored spans are structural lower bounds, and even a complete non-dialogue sentence remains pending until `animecards:restore-context` uses AI to judge whether it is understandable alone or needs the smallest useful amount of adjacent source context. Context selection defaults to Gemini Flash and may return the required span unchanged, but may never shorten it. Invalid output is retried up to three times with the validation failure and rejected output fed back to the model; the final attempt falls back to Claude Opus unless Opus was selected initially. Output is accepted only when it contains the entire required span, has complete balanced boundaries, and can be re-extracted verbatim from its chosen source window. Repeated source locations are accepted when every occurrence restores to exactly the same complete cleaned HTML; genuinely different restorations remain ambiguous. Surrounding paragraphs from repeated locations are not used as sense-selection evidence because the historical occurrence is unknown. Successful selections are stored in the append-only `.context-cache.jsonl` sidecar, so an interrupted or dry run is reusable without caching invalid attempts. Candidates without a source-backed full context are automatically deferred, omitted from enrichment and apply, and written by `animecards:report` to a `.deferred-contexts.csv` file for a later semi-manual pass unless `--include-sourceless` accepted the original context. Apply accepts only restored, semantically selected, deterministically elided, or explicitly accepted original contexts.

The enrich command uses the focused minimized-context prompt when a context is over 50 plain-text characters, so it does not ask the model to regenerate already-resolved readings, targets, sources, or senses. This hard cutoff is a prototype cost heuristic, not a product claim that every shorter context is already ideal; `card_field_generation` accepts shorter inputs, and a richer acquisition workflow can use syntactic difficulty or other evidence when deciding whether to call it. Sense selection and source-grounded hint generation are separate focused operations. Hint generation runs whenever another semantic usage is reachable from the exact front-side spelling, even if every sense compatible with the selected reading applies. For EPUB-backed candidates, sense selection receives the matched paragraph plus the nearest paragraph on each side as semantic evidence; this window remains separate from, and is never rendered as, the card's intentionally concise full context. The intended occurrences are marked deterministically before either operation sees the context. The selected reading and JMDict-compatible sense numbers are supplied as constraints; outputs outside those senses and invalid card renderings fail closed. When hint generation reports that a real contrast exists but the encounter cannot support a fair short cue, the converter records the selected usage and creates the card unhinted instead of fabricating one. Each operation retries deterministic validation failures up to three times and stores successful results in the package-wide content-addressed `generated/card-field-generation-cache.jsonl`. The enriched manifest remains the resumable stage checkpoint and makes apply purely local apart from AnkiConnect. Resumable stage outputs are fingerprinted against the complete input manifest so that review edits cannot accidentally reuse a stale checkpoint. Failed enrichments are deferred from apply, while pending enrichment on an approved candidate blocks apply until enrichment completes. The audit report lists each multi-sense candidate's selected and compatible senses, final key, hint, actual model-and-effort configuration IDs, card context, and wider sense-selection evidence. With no `--model`, each focused operation uses its evaluated production configuration; an explicit model overrides every operation while retaining its production effort. The default concurrency is 5 and can be changed with `--concurrency=N`.

The apply command is also read-only unless `--write` is present. Its preflight re-fetches every note, rejects notes edited since preparation, checks for new key conflicts, and treats already-applied entries as successful no-ops. After every write it verifies the target fields, tags, and original card ID. Results are appended to `generated/animecards-apply-YYYY-MM-DD.jsonl`. Add `--reset` to call Anki's Forget operation after conversion, returning the retained card to the new queue; this replaces the former create-a-new-card-and-delete-the-leech workflow.

Common options:

```sh
deno task animecards:prepare --limit=100
deno task animecards:prepare --query='deck:Mining note:Animecards tag:leech'
deno task animecards:prepare --word-field=Expression --sentence-field=Context
deno task animecards:prepare --output=generated/my-conversion.json
deno task animecards:prepare --anki-connect-url=http://SurfacePro11:8765
deno task animecards:prepare --epub-texts-dir=/path/to/epub_texts
deno task animecards:prepare --no-epub-source-lookup
deno task animecards:prepare --jmdict-overrides=generated/jmdict-overrides.json
deno task animecards:prepare --include-multiple-senses
deno task animecards:prepare --include-sourceless
deno task animecards:prepare --resolve-entries-with-ai --ai-model=gemini-3.6-flash
deno task animecards:restore-context generated/my-conversion.json --model=gemini-3.6-flash
deno task animecards:apply generated/my-conversion.json --limit=10
deno task animecards:apply generated/my-conversion.json --reset --write
```

For a reviewed manual decision, supply a JSON object mapping Anki note IDs to JMDict IDs, such as `{ "1234567890": "1414110" }`, with `--jmdict-overrides`. The normal spelling, reading, context, and same-spelling hint checks still apply to the selected entry.

`Word`/`Expression`/`Recognition target`, `Sentence`/`Context`, `Glossary`/`Definition`, `Reading`, `Source`, and `Source URL` are detected automatically. Field flags override this detection. The complete source snapshot in the manifest is the recovery record, so retain it until the conversion has been reviewed and synced.
